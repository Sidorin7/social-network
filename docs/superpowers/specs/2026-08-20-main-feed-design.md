# Главная лента + навигация (main layout)

Дата: 2026-08-20

## Контекст

На данный момент:
- `app/page.tsx` — дефолтный шаблон `create-next-app`, не используется по назначению.
- `app/(main)/posts/new/page.tsx` и `app/(main)/posts/[id]/page.tsx` уже реализованы и рабочие.
- `app/(auth)/login`, `app/(auth)/register` уже реализованы (shadcn/ui, react-hook-form + zod).
- `auth.ts` экспортирует `auth`, `signIn`, `signOut`, `handlers` (Auth.js v5, JWT-сессии).
- `proxy.ts` защищает `/dashboard/:path*`, `/posts/new`, `/posts/:id/edit`.
- Нет: главной ленты (списка постов), общей навигации/сайдбара для `(main)` группы, страниц профиля/настроек.

Цель: сделать `/` полноценной лентой постов с боковой навигацией, доступной и гостю (без формы создания поста), и авторизованному пользователю (с формой создания поста прямо в ленте).

## Решения (согласованы с пользователем)

1. Гость видит ленту, но вместо формы создания поста — карточка-приглашение войти/зарегистрироваться.
2. Навигация — полноценный сайдбар слева (аналог соцсетей), с двумя пунктами: **Лента** и блок пользователя внизу.
3. Профиля/настроек в коде ещё нет — соответствующие пункты в сайдбар **не добавляются** (никаких ссылок в никуда). Будут добавлены отдельным подпроектом, когда появятся сами страницы.
4. Форма создания поста для авторизованного пользователя — карточка **вверху ленты** (а не отдельная страница). `/posts/new` остаётся как есть (запасной путь, доступен напрямую по URL).
5. Лента: сортировка `createdAt desc`, без пагинации (весь список за один запрос).
6. Лайки/комментарии на карточке поста в ленте **не отображаются** (для них ещё нет логики).

## Архитектура

```
app/
  page.tsx                     ← удаляется (шаблон create-next-app)
  (main)/
    layout.tsx                 ← новый: server component, сайдбар + контент
    page.tsx                   ← новый: лента (server component)
    posts/
      new/page.tsx              (без изменений)
      [id]/page.tsx              (без изменений в логике; переиспользует PostCard для консистентности верстки)
components/
  sidebar.tsx                  ← новый: client component (usePathname)
  post-card.tsx                ← новый: карточка поста, переиспользуется в ленте и на странице поста
  create-post-card.tsx         ← новый: client component, форма создания поста (карточка) для ленты
  guest-cta-card.tsx           ← новый: карточка-приглашение войти/зарегистрироваться
```

### `app/(main)/layout.tsx`
Server component. Вызывает `auth()`, передаёт сессию в `<Sidebar session={session} />`. Двухколоночный layout (flex): сайдбар фиксированной ширины (sticky, полная высота вьюпорта), справа — `{children}` в контейнере с `max-width` и центрированием.

### `components/sidebar.tsx`
Client component (`usePathname` для подсветки активного пункта — сейчас единственный пункт "Лента", но подсветка закладывается на будущее). Содержимое:
- Логотип/название сети — ссылка на `/`.
- Пункт "Лента" — ссылка на `/`.
- Низ сайдбара: блок пользователя.
  - Если есть сессия: имя/email пользователя + кнопка "Выйти" — форма с server action, вызывающим `signOut` из `@/auth`.
  - Если сессии нет: кнопки "Войти" (`/login`) и "Регистрация" (`/register`).

### `app/(main)/page.tsx`
Server component.
1. `const session = await auth()`.
2. `const posts = await prisma.post.findMany({ orderBy: { createdAt: "desc" }, include: { author: true } })`.
3. Рендер:
   - Если `session?.user` — `<CreatePostCard />` вверху.
   - Иначе — `<GuestCtaCard />` вверху.
   - Далее список `<PostCard post={post} key={post.id} />`.
   - Если `posts.length === 0` — текст-заглушка "Пока нет постов".

### `components/post-card.tsx`
Презентационный (server-совместимый, без "use client") компонент. Принимает пост с `author` (title, content, createdAt, author.name). Верстка на базе `Card` из shadcn/ui — переиспользуется и в `app/(main)/posts/[id]/page.tsx` (там уже есть похожая инлайн-разметка, заменяем на компонент для консистентности стиля между лентой и страницей поста).

### `components/create-post-card.tsx`
Client component, логика идентична текущему `app/(main)/posts/new/page.tsx` (тот же `createPostSchema`, `createPost` server action), но:
- Обёрнута в `Card` без отдельного заголовка страницы (заголовок поменьше, в духе "Что нового?").
- После успешного сабмита — сброс формы (`form.reset()`) и `router.refresh()` вместо `router.push` — пост должен тут же появиться в ленте без ухода со страницы.

### `components/guest-cta-card.tsx`
Презентационный компонент: текст-приглашение + кнопки-ссылки "Войти" / "Регистрация" (`Button asChild` + `Link`).

## Обработка ошибок

- `createPost` уже возвращает `{ success: false, error }` при отсутствии сессии/невалидных данных — `CreatePostCard` показывает `serverError` так же, как это уже сделано в `NewPostPage`.
- Пустая лента — не ошибка, а отдельное состояние (текст-заглушка).

## Тестирование

Ручная проверка в браузере (`npm run dev`):
1. Гость на `/` — видит сайдбар, карточку-приглашение вместо формы, список постов (или заглушку, если пусто).
2. Авторизованный пользователь на `/` — видит форму создания поста, создаёт пост → пост появляется вверху ленты без перезагрузки страницы целиком.
3. Клик "Выйти" в сайдбаре — сессия завершается, UI переключается в гостевой режим.
4. Переход на `/posts/[id]` — карточка поста выглядит консистентно с лентой (тот же `PostCard`).
5. `npx tsc --noEmit` — без ошибок в новых/изменённых файлах.
